## What to build

[T-019](T-019-paste-moves-to-head.md) 定了：绳上的一件被用到，就回到绳头，和篮子里的一样。用到指 ⌥C 后 ⏎ 贴出去、在绳上点一下复制、菜单里「复制」。几件一起复制的，按它们在绳上的先后一起回到绳头。收藏的和拿在手上的留在原位。退出重开后顺序还在。

## Acceptance

- [x] ⌥C 后挑一件不是最新的，⏎ 贴出去；再按 ⌥C，选中的第一件就是刚贴的那件，和剪贴板里的一样。
- [x] 在绳上点一下复制一件，它回到绳头；其余几件的先后不变。
- [x] 几件一起复制，它们按原来的先后一起回到绳头。
- [x] 收藏的、拿在手上的被复制后留在原位。
- [x] 退出重开后，绳上的顺序是挪过之后的顺序。
- [x] 自动检查通过。原有检查里有两项假定「复制不改顺序」，只改它们的准备步骤；预期值和其余检查不改。
- [x] 真机：在文本编辑里 ⌥C 挑第三件 ⏎ 贴出，再 ⌥C，选中的是它；点一下复制另一件，它回到绳头。留截图和步骤。

## Resolution

完成，2026-11-22。实现提交 `15d3923`，分支 `feat/T-021-used-moves-to-head`。证据在本地的 `evidence/T-021/`（不进 git）。

- **怎么做的**：`Line` 复制完把复制的那几件挪到绳头，按它们原来的先后；⏎ 贴出去先走复制，所以一起生效。又复制一遍同样内容的旧路径也改走这一处。收藏的、拿在手上的不挪。挪完马上存顺序。
- **自动检查**：`scripts/check.sh` 输出 `91 strings, checked in en, zh-Hans` 和 `173 checks passed`（`check-run3.log`）。新增 9 项，走真的 `Paster`、真的卡片点击和菜单里的「复制」：贴出第三新的那件后它到绳头，再 ⌥C 选中的就是它，和剪贴板一致；点一下复制的到绳头，其余先后不变；几件一起复制，按原来的先后到绳头；重新建一个 `Line` 读回来的就是挪过之后的顺序；收藏的、拿在手上的复制后不动。没改代码时，新检查在「贴出的那件到绳头」这一项报错（`check-before.log`）。5 个故意改坏的版本都被检查抓到（`mutants.log`）。第一次跑改坏版本的结果作废，留在 `mutants-void-sdkroot-from-python-shim.log`：`/usr/bin/python3` 的外壳设了 `SDKROOT`，检查脚本没换 SDK，五个都是编译失败，不是检查报错。
- **原有检查**：两处假定复制不改顺序。一处在点 B 复制之后再点一下 C，让后面的收藏检查仍从 A、B、C 开始；一处把批量复制挪到挂上 A 之前。两处的预期值都没改。
- **真机（开发版）**：复制 5 段（探针、第1段到第4段）。在文本编辑里按 ⌥C、← ←、⏎，贴进去的是第2段，存下的顺序变成探针、1、3、4、2（`walk-03-order-after-paste.txt`）；再按 ⌥C，第2段在绳头、被选中（`walk-04-summon-again.png`）。指针停在菜单栏正中让绳子滑下来，点一下第3段，剪贴板换成第3段，顺序变成探针、1、4、2、3（`walk-06-after-click.png`、`walk-06-order-after-click.txt`）。开发版退出重开后，绳上还是这个顺序（`../T-015/walk-fixed-B.png`）。用文本编辑没用备忘录：新建的文稿关掉时直接删掉，不用再去「最近删除」里清。
- **路过的开关**：用户要的开关原本就有：菜单栏图标 → 放下晾衣绳 → 指针停在菜单栏时。真机上在菜单里关掉后，指针停在菜单栏正中，绳子不再滑下来；打开后又滑下来（`walk-09-hover-menu.txt`）。之前用这个开关存的偏好键做过同样的一遍，有截图（`walk-07-hover-off.png`、`walk-08-hover-on.png`）。用户选了位置不动。
