## What to build

文字、链接、代码默认就记。绳上挂满时，最老的一件掉进篮子，不再扔进废纸篓；篮子存在 SQLite 里。⌥C 后直接打字，搜的是绳上加篮子里的全部文字，⏎ 贴出选中的结果。退出重开，东西都还在。这一步只管文字类，图片进篮子、自动过期和清理面板留到后面的切片。依据 [T-004](T-004-retention-rules.md)、[T-009](T-009-recording-default.md)。

## Acceptance

- [x] 装好就记复制的文本、链接、代码；第一次启动说明记什么、存在哪；菜单栏能一键暂停。
- [x] 密码框里输入时、密码管理器标为私密或临时的、iPhone 通用剪贴板过来的不记，自动检查覆盖这三种。
- [x] 绳上挂满后，最老的一件掉进篮子，不再进废纸篓。存储用系统自带的 libsqlite3 加 FTS5，没有新增第三方依赖。
- [x] 同样的内容再复制一遍，不新增一件，而是挪回绳头。
- [x] ⌥C 后直接打字，搜到绳上和篮子里的文字，⏎ 贴出选中的那条。
- [x] 退出重开后，绳上和篮子里的东西都在，也搜得到。
- [x] 自动检查：连续记 200 件，第 150 件用三四个字搜得到；重新打开数据库后仍然在；同内容合并成一件。
- [x] 真机：复制 30 段文字，退出重开，⌥C 搜到最早的那段并贴进备忘录。留截图和步骤。

## Resolution

完成，2026-11-22。实现提交 `d659106`，分支 `feat/T-013-text-history-basket`。证据在本地的 `evidence/T-013/`（不进 git）。

- **怎么存的**：便签文件照旧放在数据文件夹的 `Notes/` 里，绳上有哪几件照旧记在设置里。新增 `Sources/EnCopy/History.swift`：数据文件夹里的 `History.sqlite`，每个便签文件一行，文字进 FTS5 索引（`trigram` 分词），用系统自带的 libsqlite3，`Package.swift` 没动。一件在历史里、不在绳上，就是在篮子里，这一点不另外存。数据库文件只有用户自己能读。
- **默认就记**：文字和链接不用选就记，图片还是要自己在菜单里打开。真机上开发版的设置是空的时，菜单里「文字」「链接」已经勾着，「图片」没勾。第一次启动弹出「EnCopy 会记下你复制的文字」，写了记什么、不记什么、存在 `~/Library/Application Support/EnCopy Dev` 里、怎么暂停（`walk-04-explain-recording.png`、`walk-explain-dialog.txt`）。从要先选才记的旧版本升上来的，也会看到一次。
- **暂停**：菜单「挂上复制的内容」下第一项「暂停记录」。真机上勾上后复制的一段没有记，取消后复制的一段记下了（`walk-pause.log`）。
- **不记的三种**：密码框里输入时、密码管理器标为私密或临时的、通用剪贴板过来的，各有一项检查，每项后面跟着「同一段文字不带标记就会记下」。密码框那一项检查的是「系统说正在安全输入时不记」这条规则；App 里接的是系统的 `IsSecureEventInputEnabled`，这一处只读过代码，没有在真的密码框里试。
- **掉进篮子**：绳上挂满后，最老的一件文字只从绳上落下，文件和历史里的那一行都留着。真机上复制 30 段后绳上 12 件，便签文件和历史行数一样多，废纸篓里一件都没有多（`walk-30-copies.log`）。图片挂满后照旧进废纸篓。
- **同内容合并**：按原文逐字比（大小写不同算两件）。真机上把篮子里第 05 段的文字再复制一遍，没有多出文件，它回到绳头（`walk-merge.log`）。
- **搜索和贴**：⌥C 后打字，绳上的文字和篮子里的文字用同一条查询；三个字以上走索引，一两个字逐条比对。篮子里的结果挂在绳上结果的左边，一次最多挂满一屏宽，计数显示「匹配的 / 全部」。篮子里的那件被贴出去、被点一下复制，就回到绳头。
- **退出重开**：真机上退出再打开，绳上还是 12 件，历史 32 行；在备忘录里按 ⌥C，打「9001」，绳上只剩最早的那段（它在篮子里），计数「1 / 32」，⏎ 把它贴进了备忘录（`walk-05-summoned-after-restart.png`、`walk-06-search-9001.png`、`walk-07-pasted-in-notes.png`）。这次贴入用的是第二份构建，没有重新授权，见 [T-016](T-016-stable-signing.md)。
- **自动检查**：`scripts/check.sh` 输出 `91 strings, checked in en, zh-Hans` 和 `164 checks passed`，原有 110 项没有改动（`check-final.log`）。新增 54 项，都从真的 `ClipboardWatcher` 走：往私有剪贴板写一段，看绳、文件和历史。连续记 200 段（绳上只挂 8 件），「一五零」和「一五零号」各只搜到第 150 段，重新打开数据库后还是；第 37 段再复制一遍，还是 200 行。15 个变异都让检查报错（`mutants.log`）。
- **审查**：design-integrity-review 和 behavioral-acceptance-review 都是 PASS，没有确认的问题。

真机验收时出的状况：

- 这台 Mac 上同时有另一个自动化会话在用剪贴板发消息。复制的 30 段里第 25 段没记上：它和那个会话写剪贴板落在了同一个半秒里，EnCopy 每半秒看一次，只看到后写的那条。那个会话的两条消息也被开发版记下了，所以计数是 32。开发版的数据验收完已经删掉。
- 开发版首次启动的两个提示框，两次都在十秒内被别的操作点了「开启」，不是我点的。第一次连带把开发版加进了登录项，随后在它的菜单里关掉了；验收结束时菜单里「登录时打开」没有勾。

留下的事：

- 篮子里的东西现在只能搜出来用：一次最多挂一屏宽，只能点一下复制、点叉取下、用键盘挑和贴；拖出、收藏、长按这些没接。怎么翻篮子，等下层绳那一步。
- 绳上的一件贴出去后留在原位，只有篮子里的那件用到后才回绳头。要不要都挪到绳头，见 [T-019](T-019-paste-moves-to-head.md)。
- 半秒内连着复制两次，只记后一次，见 [T-020](T-020-fast-copies.md)。
- 文字都存成文件，每件至少占 4 KB。设计方案里按每条 1.5 KB 估的，几万条时会多占几十 MB。
- 搜索在主线程上跑。历史到几万条时，一两个字的搜索要逐条比对，可能有几十毫秒的卡顿；没有量过。
- 自动检查里系统的文字识别崩过一次（崩在 Apple 的 ANECompiler 里，和这次改动无关），重跑通过。当时同时在跑三个构建。
- 从旧版本升上来、当时在提示框里点了「以后再说」的人，升级后文字会开始被记下：默认打开是 [T-009](T-009-recording-default.md) 定的，新的说明框会出现一次。
