## What to build

现在「检查更新…」只是打开发布页，要自己下 DMG、拖进「应用程序」、再点「仍要打开」。改成 EnCopy 自己看 GitHub 上的最新发布，有新版本就提醒；点「更新并重启」后，它下载 DMG、换掉自己、重新打开。

用户 2026-11-24 定的：

- 自己写，不加 Sparkle 之类的依赖。新版本从 GitHub Release 的 `EnCopy.dmg` 来，和产品页的下载链接是同一个文件。
- 默认只提醒，不自动装。设置里有「自动更新」开关，默认关。
- 没有别的 Mac，不在干净的机器上验证。

做法：

- 启动后和之后每天，向 `api.github.com/repos/a1024053774/EnCopy/releases/latest` 问一次最新版本。除了这个请求本身，什么都不发。
- 有新版本：菜单栏菜单最上面出现「更新到 x.y.z 并重启…」，设置「通用」页写着有新版本。点了先弹框给出版本号和发布说明，确认后再装。
- 装之前检查下载的 App：bundle id 和正在运行的这份一样，版本更新，签名满足正在运行的这份的指定要求（designated requirement，在这台机器上就是同一个签名证书）。有一样不对就不装，原来的 App 不动，告诉用户去发布页下载。
- 换掉的是正在运行的这份所在的位置（一般是 `/Applications/EnCopy.app`）。那里写不进去时同样不装，告诉用户。
- 换好后正常退出（照常放回截图设置），等旧进程退了再打开新的。
- 开发版（`app.encopy.EnCopy.dev`）不检查更新：发布出去的是日常那份，装上去 bundle id 也不对。

不做：

- 跳过某个版本、测试版通道、增量更新。
- 在没有这台机器签名证书的构建上更新（别的机器自己编的 ad-hoc 版本签名对不上，会被拒，只能去发布页下载）。
