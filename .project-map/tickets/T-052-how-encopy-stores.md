## What to build

用户问：复制的文件会不会多存一份、占不占地方？App 里没有地方说明。在设置的「保留」页加一节「EnCopy 怎么存」，每一类东西写一行，照代码现在的做法写，不多承诺：

- 文字、链接和代码：存成一个小文件，放在数据文件夹里；同样的内容再复制一遍不多存一份。
- 截图和从 App 里复制的图片：原图存在数据文件夹里，30 天后或超过上限时缩成缩略图。
- 录屏：存在数据文件夹里，掉下绳时进废纸篓。
- 访达里复制的文件：不复制、不建替身，只在一张清单里记下路径；文件留在原处，EnCopy 不移动也不改它；清掉时只删这张清单。
- 访达里的图片和视频：直接显示原文件，不复制；离开绳子后原文件不动。
- 最后一行：这些都只在这台 Mac 上，EnCopy 不联网；旁边一个按钮在访达里打开数据文件夹。

产品页和 README 跟着写上同样的意思。

## Resolution

完成，2026-11-24。「保留」页最下面加了一节「EnCopy 怎么存」，共六行：文字、链接和代码；截图和复制的图片；录屏；访达里的文件；访达里的图片和视频；都在这台 Mac 上。最后一行带「在访达中显示」按钮，打开的是 `DataFolder.url`。每行的说法先对过代码：文字由 `ClipboardWatcher.save` 存成小文件，同样的内容按指纹合并；复制的图片在 `Inbox.folder` 里，由 `Retention` 缩小；录屏掉下绳时由 `Line.letGo` 走 `trash`，进废纸篓；访达的文件只由 `FileList.make` 写一张路径清单；访达的图片和视频挂的是原文件，离开绳子时只 `drop`。EnCopy 没有联网的代码，「检查更新…」只是打开发布页。产品页在「只在这台 Mac 上」后面加了一张「文件不多存一份」，README 中英文各加一条。提交 `c7b961f`。

用户说的是「软连接」，实际没有建任何链接，只有一张记路径的清单；页上写的是「不复制，也不建替身」。
