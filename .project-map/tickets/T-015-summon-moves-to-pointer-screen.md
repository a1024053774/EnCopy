## What to build

[T-012](T-012-summon-and-paste.md) 留下的一种情形。绳子已经露在一块屏上时（新东西挂上来露出的 2.5 秒里，或者被「显示晾衣绳」钉住时），指针在另一块屏上按 ⌥C，搜索框出现在绳子所在的那块屏，不在指针所在的屏。依据 [T-008](T-008-summon-position.md)。从代码读出来的，没有在真机上复现过。

排在 [T-016](T-016-stable-signing.md) 后面：改代码要重新构建，签名没固定之前，每次重新构建都要用户重新授权辅助功能。

## Acceptance

- [x] 先在真机上复现：绳子露在 A 屏时，指针放到 B 屏按 ⌥C，记下搜索框出现在哪块屏。
- [x] 改完后同样的步骤，绳子和搜索框都在 B 屏顶部。
- [x] 自动检查通过，原有检查不改。
- [x] 顺带量一次第一次 ⏎ 从按键到文字出现用了多久（T-012 里出现过一次超过 1.6 秒）。量到的是开发版打开后的第一次；「刚授权后的第一次」要用户重新授权，移到 [T-022](T-022-first-paste-after-authorizing.md)。

## Resolution

完成，2026-11-22。实现提交 `492048a`，分支 `feat/T-015-summon-on-pointer-screen`。证据在本地的 `evidence/T-015/`（不进 git）。

- **复现**：没改之前的开发版（只带 T-021），内建屏 A 加一块临时虚拟屏 B（1920×1080，摆在 A 右边）。指针在 A 时复制一段，绳子在 A 露出来；指针挪到 B 的正中按 ⌥C，绳子（x=0，宽 1710）和搜索框（x=685）都在 A，B 上什么都没有（`walk-repro-windows.txt`、`walk-repro-A.png`、`walk-repro-B.png`）。
- **怎么改的**：⌥C 时只有绳子就在指针那块屏上，才原地接管键盘；露在别的屏上，就当成一次新的叫它来，挪到指针所在的屏。
- **改完**：这时用户接上了外接屏（2490W1，1920×1080，主屏），改用两块真屏：外接屏 B 在左，内建屏 A 在右。指针在 A 时复制一段，绳子在 A 露出来（x=1920）；指针挪到 B 按 ⌥C，绳子（x=0，宽 1920）和搜索框（x=790，B 的正中）都在 B（`walk-fixed-windows.txt`、`walk-fixed-B.png`），再按 ⌥C 收起。绳子露在 A、指针也在 A 时按 ⌥C，绳子留在原地，搜索框在它下面（x=2605，`walk-same-screen-windows.txt`）。
- **贴的时间**：开发版打开后的第一次 ⏎，从按键到文字出现在文本编辑里 221 毫秒，第二次 116 毫秒（`walk-paste-latency.txt`；`evidence/tools/pastetime` 发回车后每 5 毫秒读一次文本框）。授权在固定签名下一直有效，量的不是「刚授权后」，那一项见 [T-022](T-022-first-paste-after-authorizing.md)。
- **自动检查**：`scripts/check.sh` 输出 `91 strings, checked in en, zh-Hans` 和 `173 checks passed`（`check-final.log`），这一单没改检查。⌥C 落在哪块屏的逻辑在 `AppDelegate` 里，检查程序不编译它，这一条只有真机证据。

验收时出的状况：

- 虚拟屏一建出来就成了主屏，内建屏去镜像它，用户屏幕上的画面变成 1920×1080，约一分钟后用 `evidence/tools/unmirror` 关掉镜像、把它摆到内建屏右边。用户接上外接屏后，虚拟屏停掉了。
- 开发版的两个首次启动框在它打开两秒内就被点了：截图接管打开，开发版进了登录项。验收完在它的菜单里关掉了登录项，系统的登录项列表里已经没有 EnCopy Dev。开发版退出后，系统截图位置回到日常版的文件夹。
- 内建屏的菜单栏太挤，开发版的图标被刘海挡住，辅助功能也找不到它的菜单；接上外接屏后在外接屏的菜单栏里才点到。
- 日常版退出期间，用户复制的两段文字（20:59、22:10）只被开发版记下，`scripts/clean-dev.sh` 删开发版数据时一起删了；22:10 那段验收结束时还在剪贴板上，没有动。
- 第一次在文本编辑里量贴的时间时，文本编辑开着「打开」面板、没有文稿，⌘V 落在面板上，什么也没打开；新建文稿、重开开发版后重量。
